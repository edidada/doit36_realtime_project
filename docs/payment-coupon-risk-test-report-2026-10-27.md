# 支付/优惠券风控验收报告（2026-10-27）

## 环境和范围

Win11、Oracle JDK 17.0.12、Maven 3.9.11、普通 CPU；HTTP 应用使用 `-Xmx256m`，H2 嵌入式数据库。工程仍在 `master` 开发，未部署到现有 K3s。

本次 `mvn -B -ntp verify` 全 Reactor 7 个工程通过；风险模块共 46 个断言测试通过（原数值计算 17 个，新增支付/优惠券/HTTP/数据和策略边界 29 个），FIN-OLAP 原有 21 个测试也通过。共 67 个实际断言测试通过；不复用旧 GitHub Actions 来证明新代码。

## 全流程覆盖

| 场景 | 已执行断言 |
| --- | --- |
| 正常领券/扣款 | 服务端价 10000 分，减券 2000 分，实扣 8000 分，券 USED |
| Bob 盗用 Alice 券 | BLOCKED，不扣钱，券仍 AVAILABLE |
| 重复请求、改参数复用 key | 同参回原支付，改参数 409 |
| 他人订单/支付/退款、客户自审 | 资源 404 / 角色 403 |
| 同券并发核销 | 两个独立订单只允许一次成功 |
| 同 key 16 路请求 | 只有一笔通道账和一次扣款 |
| 活动最后一张券并发领取 | 只发一张，库存不为负 |
| 同设备多账号领券 | 一个成功，其余拦截 |
| 过期/非适用商户/未满门槛 | 对应理由拦截 |
| 封禁用户、商户、受损设备 | 不调用模拟 PSP |
| 新账号+陌生设备+代理/异地 | 综合规则拦截 |
| 陌生网络、近期改密、余额搬空 | 待审核且不扣款 |
| 审核通过/拒绝/用户取消 | 独立权限校验，拒绝/取消释放订单与锁券 |
| 审核期间优惠券过期 | 即使操作员请求通过也被拒绝 |
| 连续拒付/10 分钟高频 | 达阈值拦截，不因更换 key 绕过 |
| PSP 拒付 | 钱包不变，券释放 |
| PSP 已扣款但返回超时 | PENDING/RESERVED，重试不重复扣款 |
| 通道长时间不可用 | PENDING，未得明确结果不释放券 |
| 文件数据库重启恢复 | 已扣款未确认的支付通过对账变 PAID |
| 退款已完成但业务未落库 | 恢复变 REFUNDED，不重复退钱 |
| 退款套利 | 只退净支付金额，券 VOID，不能再次核销 |
| HTTP 伪造字段/重复 JSON/大 body | 400/413，不能覆盖金额和实名 |
| 公开数据预测泄漏检查 | 特征不含交易后余额或标签；改 holdout 标签不改变树 |

Win11 `demo-test.ps1` 实际启动独立 Java 子进程并完成 14 个验收断言；测试后停止自身进程，合成数据与日志保存在 `.artifacts/fraud/acceptance-<ID>/`。

### 固定规则基线（全 50000 行）

| TP | FP | TN | FN | precision | recall | FPR |
| --- | --- | --- | --- | --- | --- | --- |
| 93 | 11527 | 38373 | 7 | 0.8003% | 93% | 23.1002% |

规则在转账/取现且金额至少 200000 原单位，或金额至少 1000 原单位且达到交易前余额 95% 时预测拦截。该基线误报明显过高，保留作为不足证据；它不是在线多因素规则的准确率，也没有部署到 API。

### CPU 决策树（独立测试后缀 15000 行）

训练前缀 35000 行含 90 条欺诈；测试后缀含 10 条欺诈。固定最大深度 4、最小叶 20、训练权重封顶 100。仅使用交易类型、金额和交易前余额派生特征。

| TP | FP | TN | FN | precision | recall | FPR |
| --- | --- | --- | --- | --- | --- | --- |
| 10 | 52 | 14938 | 0 | 16.1290% | 100% | 0.3469% |

这是同一个合成数据前缀的源顺序 70/30 切分，只有 10 个测试欺诈样本，不能据此宣称生产召回 100%。与上表测试集合不同，不能直接把两行指标当同一个测试集的提升量。没有独立验证集、调参搜索、概率校准、真实分布或概念漂移验证；树不接入线上放行路径。

公开数据前 20 条还通过 `dataset simulate` 驱动本应用的真实订单、规则和模拟通道。除金额/余额外，资料均明确标为合成；这些场景不参与准确率宣称。优惠券盗用属于单独构造的对抗场景，PaySim 没有对应标签。

最终公开数据场景演练：7 条 BLOCKED、12 条 REVIEW、1 条 PAID。前缀第 3/4 条达到余额搬空规则，均为 REVIEW，余额未变；这与离线树的分类评估是两种不同的测试，不能混用指标。
